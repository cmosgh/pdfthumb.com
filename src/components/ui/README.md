# UI primitives (#146)

**Pages compose, primitives style.** Every colour, border, radius, shadow,
typography class and opacity in the app lives in this folder. Pages and
feature components pick a primitive and a named variant
(`<Card variant="panel">`), never Tailwind colour or type classes.

## The rule: layout vs style

- **Layout belongs to the caller**, through `className`: padding, margin,
  gap, flex and grid, width and height, position, display, overflow, text
  alignment, whitespace and word breaking.
- **Style belongs here**: colour, border (and its width), divide, ring,
  outline, radius, shadow, opacity, gradients, and typography (size, weight,
  family, leading, tracking, case, underline, list markers).
- **Exceptions** where a primitive carries its own layout, because the
  layout is part of what it is: Button sizes (padding and text size) and
  the one-off buttons' display, Badge (padding and display), IconButton
  (the `p-2` sets its hover background), Tabs, Table cell padding (by
  `density`), Dialog (backdrop and panel), Switch, Progress, NavItem,
  NavSkeleton, IconTile, Spinner (`mx-auto`), Input (`px-3 py-2`),
  CodeBlock (`p-4 overflow-x-auto`), FramedImage (`mx-auto`).
- **Keep typography on the block.** Don't move a text size from a block
  onto an inner `<span>`: the block's strut keeps the line box at the
  inherited size. That's why Card `field` carries `text-sm text-fg-strong`
  and `Td` carries `text-sm` (or `text={false}` for a badge-only cell).
- **Named variants, not Tailwind-in-props.** Add a variant here rather than
  passing a colour class from a page.
- **Pixel-exact first.** Each variant is exactly the class set its call
  sites had before #146. Near-duplicates stay separate variants and are
  listed under "Merge candidates"; merging them is a visible design change
  for a later ticket.
- Every class is a complete literal in source, so Tailwind's scanner sees
  it. Never build a class name by concatenation. Merge with `cx()`.
- Router links: `createLink` from `@tanstack/react-router` wraps the anchor
  primitives (`RouterButtonLink`, `RouterTextLink`, `RouterNavItem`), so
  they take `to`, params and preloading. TanStack adds its `active` class
  and `aria-current` as any `Link` does.

## Findings recorded while extracting

- **PricingCard disabled opacity:** the button had both `opacity-50` (the
  Button's disabled style) and `opacity-70` (its className). In the built
  CSS `.opacity-70` comes after `.opacity-50`, so 0.7 showed. That's
  `disabledLook="soft"`.
- **Overage featured column heading:** it had `font-medium` and
  `font-bold`. Tailwind v4 emits `.font-medium` after `.font-bold`, so it
  rendered medium. `Th` has no "featured" prop; making it bold is a visible
  change for the design ticket.

## Merge candidates (for a later design ticket)

Each pair or group differs visibly today and was kept apart to stay
pixel-exact.

- Buttons: the marketing `primary`, the action `accent`, and the one-offs
  `navCta` (`shadow-md`, `text-sm`, `py-2 px-4`, scale), `swagger` (no ring,
  no scale, 16px) and `session` (`rounded-lg`, `py-2.5`): five accent
  buttons. `google` vs a neutral/outline button.
- Marketing sizes: `sm` was unused and dropped.
- Card: `panel` (`shadow-sm`) vs `raised` (`shadow-lg shadow-elevation/50`)
  for cards on the same settings page; `feature` vs `pricing` (`rounded-lg`
  vs `rounded-xl`, hover shadow); `well` vs `wellOutlined` vs `band`
  (`rounded-lg` vs `rounded-xl`, border colour); `tooltip` vs `panel`.
- Dialog: `md` and `lg` differ only in max width; `session` differs in
  radius, shadow, padding and the dimmed backdrop.
- Callout: `danger` (`rounded-lg`, bordered) vs `dangerCompact`
  (`rounded-md`, no border).
- Text links: `link` vs `underline` hover; `nav` vs `navSm` (size,
  transition) vs `footer` (tone); `status` is `navSm` in link colour.
- IconButton: `round` vs `square` (radius, tone, hover colour); `bare` has
  no hover background.
- Table: three frames and three densities; cell tones `fg` vs `fg-strong`
  for the first column, `fg-muted` vs `fg-label` for the others.
- Surface: `bar` (`shadow-sm shadow-elevation`) vs `menu` (`shadow-lg`, no
  tinted shadow) vs `sidebar`.
- Headings: `3xl` bold (dashboard h1) vs `page` bold vs `section`
  extrabold; `lg semibold` card titles in `fg-strong` vs `fg` (settings);
  `xl` bold vs semibold.
- Code: `chip` has no `font-mono`, unlike `inline` and `key`.
- Radius: NavItem and Callout use `rounded-lg` where buttons use
  `rounded-md`.
